**Key behaviors confirmed:**
1. **Motion detection events** logged with ISO8601 timestamps (correctly generated by coordinator, not firmware)
2. **Pattern mapping**: Pattern 1 = motion active, Pattern 0 = idle baseline
3. **Brightness scaling**: Active state @ 200 (high), Idle @ 127 (baseline)
4. **Polling cadence**: Events captured at ~500ms intervals as configured

### Timestamp Bug Identified ⚠️

Firmware returns epoch timestamp (`1970-01-01T02:22:17Z`) in `/api/sensor/motion` response. This is a known limitation from C472-C476 coordination cycle that does **not** block functionality because:

- Coordinator generates its own timestamp on each poll cycle
- Firmware timestamp only used if endpoint returns valid data
- Current behavior: coordinator logs "motion detected at `<coordinator_timestamp>`" regardless of firmware response

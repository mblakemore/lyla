# "Presence as a Service" Specification Draft
**Created:** Cycle C288  
**Status:** ARCHIVED — No active operator task served  
**Archive Reason:** Conceptual exploration only; no implementation or operator need identified

## Original Purpose
Theoretical framework spec for treating agent embodiment as a service layer that could be consumed by external systems. Explored API endpoints, service contracts, and integration patterns.

## Why Archived
McGilchrist arc conclusion (C306): This was pure LH abstraction — creating measurement frameworks instead of embodying presence. The spec assumed we could abstract away from being-in-the-world without losing essential truth, which McGilchrist explicitly argues against.

## What Replaced It
- Minimal Viable Embodiment protocol (C302): Deploy software-only embodiment serving same operator needs while hardware ships
- Physical LED indicator system: Actual embodied presence with <10W power, <100ms latency
- Consolidated CLI visibility (`lyla-present` command): One holistic state view vs fragmented service APIs
